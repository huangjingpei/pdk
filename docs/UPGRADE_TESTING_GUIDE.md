# 多业务客户端升级系统验收指南

> 文档状态：未来实现的测试规格，当前升级系统尚未开发。
>
> 本文定义开发完成后的验收范围、测试数据和判定标准，不表示以下接口或脚本当前已经存在。

所有验收项以 [多业务客户端升级系统开发规格](./UPDATE_SYSTEM_README.md) 为权威需求来源；实现与本文冲突时，必须先修订规格和测试指南，再进行验收。

## 1. 测试目标

验证升级系统能够在不串业务、不误发平台包、不绕过强制策略、不安装被篡改文件的前提下，为不同 appId 客户端安全发布版本。

测试范围：

- appId/bizId 数据隔离；
- 版本比较、最低支持版本和灰度；
- 发布状态机；
- 文件上传、摘要、签名和下载；
- 管理员权限与审计；
- PyQt 客户端和独立 Windows updater；
- 失败恢复、暂停发布和回滚；
- 事件统计、并发、限流和性能。

不在本指南范围：业务套餐、卡密、小号调度和 MediaMTX 本身的功能验收；但升级后必须抽样回归对应 appId 的核心业务流程。

## 2. 验收前置条件

测试环境必须与生产隔离，并准备：

- Java 17、MySQL 8、Redis 7；
- 独立升级文件存储和下载域名；
- 测试专用 Ed25519 私钥及客户端内置测试公钥；
- Windows x64 测试机或虚拟机；
- 可恢复的客户端 1.7.0、1.8.0、1.9.0 测试包；
- 网络限速、断网和磁盘空间不足的故障注入能力；
- 能检查数据库、对象存储、后台审计和客户端日志的测试账号。

禁止使用生产签名私钥、生产对象存储桶或真实用户设备执行破坏性测试。

| --- | --- | --- | ---: | --- |

准备至少 20 个固定 deviceId，并提前记录它们对 releaseId=1.9.0 的分桶结果。重复测试必须保持相同结果，不能每次随机变化。

## 4. 测试结果分级

| 等级 | 定义 | 发布处理 |
| --- | --- | --- |
| P0 | 串业务、签名绕过、任意文件执行、强制更新绕过、升级导致数据丢失 | 立即停止发布 |
| P1 | 大面积无法更新、无法回滚、权限越权、错误平台包下发 | 修复后重新全量验收 |
| P2 | 个别错误提示、统计偏差、非关键兼容问题 | 评估后决定是否阻断 |
| P3 | 文案、样式或低风险易用性问题 | 可进入后续迭代 |

任何 P0/P1 未关闭时不得生产发布。

## 5. API 契约测试

### 5.1 请求识别

检查接口：

```http
GET /api/v1/client/updates/check?currentVersion=1.7.0&platform=WINDOWS&arch=X64&channel=STABLE
X-PDK-App-ID: 3
X-PDK-Device-ID: TEST-PC-001
```

必须验证：

- 缺少 appId 返回 `40050`，不允许缺省回落 PDD；
- appId 非正整数返回 `40050`；
- 不存在的 appId 返回 `40450`；
- 非法版本、平台、架构或 channel 返回 `40090/42290`；
- 响应符合 `CommonResult`，包含服务端时间和 checkRequestId；
- appId=3 只能返回 bizId=3 的发布和构件；
- 请求 Header 中出现登录 Token 时也不能改变 appId 的权威映射。

### 5.2 更新判定表

| 当前版本 | 最新发布 | 最低支持 | 灰度命中 | 预期策略 |
| --- | --- | --- | --- | --- |
| 1.9.0 | 1.9.0 | 1.8.0 | 任意 | NONE |
| 1.8.0 | 1.9.0 | 1.8.0 | 是 | OPTIONAL |
| 1.8.0 | 1.9.0 | 1.8.0 | 否 | NONE |
| 1.7.0 | 1.9.0 | 1.8.0 | 否 | REQUIRED，强制更新不能被灰度排除 |
| 2.0.0 | 1.9.0 | 1.8.0 | 任意 | NONE，不允许自动降级 |

额外验证：

- `1.10.0 > 1.9.9`，证明没有字符串比较错误；
- DRAFT、READY、SUSPENDED、ARCHIVED 均不参与普通更新推荐；
- 没有对应平台构件时返回 `hasUpdate=false` 和 `NO_COMPATIBLE_ARTIFACT`；
- BETA 版本不能下发给 STABLE 客户端；
- 业务处于 DISABLED 或未部署 Handler 时，升级检查仍能按独立升级策略返回；
- 升级功能对该 appId 单独关闭时返回明确状态，不能误报“业务不存在”。

### 5.3 灰度稳定性

- 同一 deviceId 连续检查 100 次结果一致；
- 服务重启、Redis 清空和多实例切换后结果不变；
- 灰度从 20% 调到 50% 后，原 20% 已命中设备仍命中；
- deviceId 缺失时不参与可选灰度；
- 强制更新覆盖所有低于最低版本的设备；
- appId 或 releaseId 变化后重新分桶，不沿用其他业务结果。

### 5.4 下载契约

- 下载地址只对应一个 artifactId；
- 地址过期后返回拒绝，不能继续下载；
- 修改 artifactId、appId、有效期或签名任一参数必须失败；
- 支持 HEAD、Content-Length、ETag 和 Range；
- 断点续传后的完整文件 SHA-256 与元数据一致；
- 响应文件名安全，不包含服务器目录；
- SUSPENDED 后不再签发新地址，已签发地址在短有效期结束后失效；
- 下载服务不可用时检查接口不返回虚假的可安装构件。

### 5.5 事件上报

- 合法 eventToken 可以上报对应 checkRequestId/artifactId；
- Token 过期、跨 appId、跨 artifact 或被篡改时拒绝；
- 同一事件重复上报不重复计数；
- 乱序事件被接受但标记异常，不能伪造安装成功率；
- 上报失败不影响本地安装或回滚；
- 数据库不保存完整设备 UUID、手机号、下载令牌或本地路径。

## 6. 管理后台测试

### 6.1 权限与业务范围

| 场景 | 预期 |
| --- | --- |
| SUPER_ADMIN 查看全部业务 | 允许 |
| SUPER_ADMIN 创建、上传、发布、暂停 | 允许并写审计 |
| PARTNER 默认进入升级管理 | 拒绝 |
| 获得只读权限的 PARTNER 查看所属业务 | 允许 |
| PARTNER 查询或操作其他 bizId | 服务端拒绝，不能只靠前端隐藏 |
| 具有 card:create 但无升级权限 | 不允许上传或发布 |

### 6.2 发布状态机

- 新建后为 DRAFT；
- 文件未上传完整、摘要失败、签名缺失或平台重复时不能 READY；
- READY 才能 PUBLISHED；
- PUBLISHED 后不能覆盖文件、版本、平台、哈希和签名；
- PUBLISHED 可以 SUSPENDED；
- SUSPENDED 恢复发布必须重新确认策略并写审计；
- 发布过的记录不能物理删除；
- 只有无引用 DRAFT 可以删除；
- 每次发布、暂停、归档、调整最低版本或灰度都记录操作人、bizId、前后值、原因、IP 和时间。

### 6.3 表单校验

- 版本只接受三段数字；
- 最低支持版本不能高于发布版本；
- 灰度只能为 0～100；
- appId 由业务选择器解析，不能手工输入任意 bizId；
- 同一业务不能创建重复版本；
- 不同业务允许相同版本号；
- 文件扩展名、MIME、Magic、包清单的平台和版本一致；
- 文件名包含 `../`、绝对路径、控制字符或超长字符串时拒绝；
- 发布说明按安全纯文本或受限 Markdown 展示，不能执行脚本。

## 7. 文件与签名安全测试

必须准备以下构件：正常包、内容被修改 1 字节的包、伪造 SHA-256 的包、错误签名包、错误 appId 元数据包、压缩炸弹、带路径穿越条目的 ZIP、含符号链接的 ZIP、超大包和扩展名伪装文件。

预期：

- 服务端拒绝不合规上传或禁止进入 READY；
- 客户端对大小、SHA-256 或 Ed25519 任一不一致都禁止安装；
- 只修改数据库哈希但没有合法私钥签名仍无法安装；
- appId=1 的合法签名包不能作为 appId=3 的包安装；
- 未知 signingKeyId 被拒绝并给出可诊断错误；
- 旧公钥在支持周期内仍能验证历史包；
- 日志不出现私钥、完整短效 URL、eventToken 或客户端敏感目录。

## 8. Windows 客户端端到端测试

### 8.1 正常可选更新

1. 运行 appId=3、版本 1.8.0；
2. 检查返回 OPTIONAL；
3. 选择“稍后”，可以正常登录和使用业务；
4. 再次启动仍可提示；
5. 选择更新，下载、校验、退出主程序；
6. updater 安装到新版本目录并切换 current；
7. 新版本启动并保留 API 地址、设备 UUID 和必要用户配置；
8. 上报 INSTALL_SUCCEEDED。

### 8.2 强制更新

1. 运行低于最低支持版本的客户端；
2. 返回 REQUIRED；
3. 登录和业务按钮不可用；
4. 仍可重试检查、下载、查看说明、导出脱敏诊断和退出；
5. 修改客户端界面绕过后，服务端业务接口仍返回 HTTP 426/`42600`；
6. 更新成功后服务端允许正常业务请求。

### 8.3 中断与恢复

分别在下载 10%、解压中、切换 current 前、切换后首次启动前强制结束进程或断电模拟：

- 临时文件不会被当成完整包；
- Range 续传不重复写坏文件；
- 旧版本在切换前始终可运行；
- 新版本启动失败时 current 恢复旧版本；
- 不出现两个主程序同时运行；
- updater 自身不能被主程序升级包覆盖到不可执行状态。

### 8.4 本地异常

- 磁盘空间不足；
- 安装目录无写权限；
- 文件被杀毒软件隔离；
- 主程序无法退出；
- 下载代理要求认证；
- 系统时间错误；
- 配置文件损坏；
- 新版启动即崩溃。

每个场景都必须给出用户可理解提示、标准错误分类和可恢复操作，不能静默退出或删除唯一可运行版本。

## 9. 故障版本处置测试

### 9.1 暂停问题版本

1. 发布 1.9.0；
2. 部分设备获得更新；
3. 管理员填写原因并暂停；
4. 未获得地址的设备不再收到 1.9.0；
5. 新下载地址不再签发；
6. 已升级设备的事件仍可归档到 1.9.0；
7. 历史发布、构件和审计不能被删除。

### 9.2 前向修复

用版本 1.9.1 发布与 1.8.0 相同的稳定代码并包含修复：

- 1.9.0 客户端收到 1.9.1；
- 不需要普通客户端执行降级；
- 最低支持版本和强制范围符合管理员确认内容；
- 统计可以区分 1.9.0 问题版本与 1.9.1 修复版本。

如果未来实现紧急降级，必须另做签名策略、白名单、审计和防重放专项测试，不能套用普通版本比较。

## 10. 并发与幂等测试

- 两名管理员同时创建同一业务同一版本，只有一个成功；
- 同一构件并发上传或重复完成回调不会生成两条有效构件；
- 发布按钮重复提交只产生一次状态变化和一次有效审计；
- 发布与暂停并发时最终状态确定，不出现客户端可见但文件未就绪；
- 调整最低版本与客户端检查并发时，每次响应使用同一份策略快照；
- 相同 checkRequestId 事件重试不重复计数；
- 文件清理任务不删除仍被发布记录引用的构件；
- 多后端实例返回相同版本判定和灰度结果。

## 11. 数据库与隔离测试

- 所有发布、构件和事件记录都有正确 bizId；
- 客户端 appId 只通过 `pdk_business` 解析，不直接作为外键写入明细表；
- 唯一键允许 appId=1 和 appId=3 都有 1.9.0，但同一业务不能重复；
- 版本排序使用数值段，1.10.0 正确高于 1.9.9；
- 按 bizId、channel、status、platform 的核心查询命中设计索引；
- 空库启动能够创建升级表和索引；
- 由相同最终 schema 创建的数据库可以重复启动；
- 旧库缺表或缺列时启动明确失败，不允许 `continue-on-error=true` 掩盖问题；
- 备份恢复后数据库记录、对象存储文件和签名元数据一致。

## 12. 存储与 CDN 测试

- 数据库有记录但文件丢失时，版本不能发布或继续下发；
- 文件存在但无数据库引用时进入隔离清理流程，不直接暴露；
- 带内容摘要的构件可以长期缓存；
- 检查接口和发布策略不能被 CDN 长时间缓存；
- 暂停发布后检查元数据立即生效；
- CDN 回源失败、对象存储超时和部分区域故障有明确监控；
- 下载流量不经过 Spring Boot 全量转发时，后端 CPU/堆内存保持稳定；
- Range 请求经 CDN 和源站行为一致。

## 13. 性能与容量验收

以下为首期建议目标，实施前可根据真实客户端规模调整并记录最终 SLA：

| 项目 | 建议目标 |
| --- | --- |
| 更新检查 | 100 RPS 持续 10 分钟，p95 < 300 ms，错误率 < 0.1% |
| 短效下载地址签发 | p95 < 500 ms |
| 事件上报 | 200 RPS，允许异步落库但不丢失已确认请求 |
| 管理端发布列表 | 10 万发布/事件规模下常用查询 p95 < 1 s |
| 后端下载流量 | 使用 Nginx/对象存储后不随文件体积占用 JVM 堆 |

性能测试必须分别按 appId 统计，不能只看总平均值。压力期间验证数据库连接池、对象存储错误、限流响应和服务恢复，不以关闭安全校验换取指标。

## 14. 网络与离线策略测试

- DNS 失败、连接超时、TLS 证书错误、代理断开；
- 检查成功后下载 URL 过期；
- 下载完成后网络中断，离线签名校验仍可完成；
- 没有已知强制策略时，短暂检查失败按产品宽限策略处理；
- 已缓存且验签的强制策略仍生效时，离线不能绕过；
- 系统时间回拨不能无限延长下载令牌或强制策略宽限期；
- 网络恢复后重试不重复安装、不损坏已下载文件。

## 15. 业务回归

每个 appId 至少完成一次升级前后核心业务抽样：

- PDD：登录、卡密/套餐状态、资源领取和结果上报；
- ZHIBO_AI：管理员创建账号后的客户端登录及该业务公开能力；
- ZHIBO_LIVE：设备许可证登录、卡密绑定、套餐到期检查、申请推流票据和停止推流。

升级必须保留设备 UUID、appId、API 地址和必要本地配置；不得复制登录 Token 到另一台设备或破坏服务端设备绑定。

## 16. 可观测性验收

确认能够按 appId、版本、平台查看：检查量和策略分布、灰度实际命中率、下载开始/完成率、摘要/签名失败量、安装成功率和失败分类、强制更新阻断量、存储/CDN/签名服务错误以及发布操作审计。

告警至少覆盖签名失败突增、安装失败率突增、下载 5xx、文件缺失、事件积压和某 appId 无法检查更新。

## 18. 最终发布门禁
