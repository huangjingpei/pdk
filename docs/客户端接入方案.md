# PDK 客户端接入方案

> 接入基线：[`client/python/pdk_client.py`](../client/python/pdk_client.py)
>
> 适用版本：当前仓库 Spring Boot、PDD、ZHIBO_AI、ZHIBO_LIVE 实现
>
> 最后核对：2026-08-31

本文是客户端接入方的主文档。接口、字段和流程已按当前代码核对：

- `ClientAuthController`、`ClientAccountController`、`ClientDeviceLicenseController`；
- `DeviceSecurityInterceptor`、`DeviceLicenseService`；
- `ZhiboLiveClientController`、`LiveStreamSessionService`；
- `ClientCryptoAdvice`、`BodyCryptoService`；
- `schema-mysql.sql`、Python 单文件客户端和 PyQt 调试客户端。

旧文档中 AES-128 字节翻转是**业务资源密文**，不是 HTTP 请求信封；JWT 也不是本项目鉴权方案。客户端会话使用 Sa-Token，并必须把 Token 当作不透明字符串处理。

---

## 1. 先理解三个业务

当前数据库种子有三个业务。`appId` 是客户端公开标识，`bizId` 是服务端数据库关联键；客户端只配置 `appId`，不得自行传 `bizId`。

| appId | bizCode | 授权模型 | 注册模式 | 当前种子状态 | 客户端重点 |
|---:|---|---|---|---|---|
| 1 | `PDD` | `USER_SUBSCRIPTION` | `SELF_SERVICE` | `ACTIVE` | 短信注册、用户级套餐、单设备绑定、资源调度与成功扣次 |
| 2 | `ZHIBO_AI` | `DEVICE_LICENSE` | `ADMIN_ONLY` | `DISABLED` | 管理员建账号和分卡；一卡一机；可使用 zhibo 聚合资源动作 |
| 3 | `ZHIBO_LIVE` | `DEVICE_LICENSE` | `ADMIN_ONLY` | `DISABLED` | 一卡一机；登录后申请短效推流票据，由 MediaMTX 再鉴权 |

`ZHIBO_AI` 和 `ZHIBO_LIVE` 共用 `zhibo` 业务实现目录，但用户、套餐、卡密、许可证、资源和会话仍按不同 `bizId/appId` 隔离，Token 不能跨业务复用。

部署时同时受两层开关控制：

1. 数据库业务状态；
2. `PDK_ENABLED_BIZ_CODES` 部署白名单和对应 Handler 健康状态。

因此，正式客户端启动后必须先读取业务元数据，不能只根据本地 appId 假定业务可用。

---

## 2. 接入文件与安装

接入方只需复制或直接引用：

```text
client/python/pdk_client.py
```

安装依赖：

```powershell
python -m pip install requests cryptography
```

最小初始化：

```python
from pdk_client import PdkClient, PdkClientError

client = PdkClient(
    base_url="http://127.0.0.1:8080",  # 仅本地开发允许 HTTP
    app_id=3,
    phone="13454118763",
)
```

生产初始化：

```python
client = PdkClient(
    base_url="https://api.example.com",
    app_id=3,
    phone="13454118763",
    require_https=True,
    verify_tls=True,
    use_crypto=True,
    public_key_pin="由可信渠道预置的32位hex公钥指纹",
)
```

生产客户端应在构建配置中固化 `base_url + appId + bizCode`，不能把 appId 切换入口暴露给最终用户。

## 3. 通用协议

### 3.1 响应成功不能只看 HTTP 200

业务接口统一返回：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {},
  "timestamp": 1788100000000
}
```

多数业务异常仍可能使用 HTTP 200 返回，因此唯一业务成功条件是 `code == 200`。`PdkClient` 已统一处理：

- 成功：方法直接返回 `data`；
- 业务失败：抛 `PdkClientError`；
- 网络失败：抛 `PdkClientError(code=0)`。

```python
try:
    profile = client.profile()
except PdkClientError as exc:
    print(exc.code, exc.message, exc.action, exc.retryable)
```

### 3.2 appId 规则

SDK 每次请求都发送：

```http
X-PDK-App-ID: 3
```

登录、注册、短信、改密和卡密核销等请求体也包含同一个 `appId`。请求头与请求体不一致返回 `40050`。

### 3.3 登录后安全请求头

登录成功返回动态 `tokenName` 和 `tokenValue`。后续受保护请求必须带：

```http
X-PDK-App-ID: 3
X-PDK-Phone: 13454118763
X-PDK-Device-ID: PDK-稳定设备指纹
<tokenName>: <tokenValue>
```

不要硬编码 Token 头名，也不要解析 Token 内容。`PdkClient` 会自动读取登录响应并添加上述请求头。

### 3.4 公开与受保护接口

| 类别 | 接口 | 是否需要登录 Token |
|---|---|---:|
| 业务发现 | `/api/v1/client/business/by-app/{appId}` | 否 |
| 加密配置 | `/api/v1/client/config/public` | 否 |
| 短信/注册/登录/改密/重置密码 | `/api/v1/client/auth/...` 对应接口 | 否；改密靠旧密码校验 |
| PDD 卡密核销 | `/api/v1/card/activate` | 否；请求体包含手机号和 deviceId |
| 注销/解绑 | `/api/v1/client/auth/logout`、`unbind-device` | 是 |
| 账号/许可证查询 | `/api/v1/client/account/...`、`device-license/...` | 是 |
| 资源调度 | `/api/v1/dispatch/...` | 是 |
| 直播票据与会话 | `/api/v1/client/zhibo-live/...` | 是，并要求有效设备许可证 |

重要修正：`/api/v1/card/activate` 当前不经过设备登录拦截器；它是 PDD 的公开原子核销接口，不应误写成必须携带 Sa-Token。它仍应通过 HTTPS/信封保护请求体。

## 4. 客户端启动顺序

推荐每次启动执行：

```python
from pdk_client import PdkClientError

try:
    business = client.ensure_business_available(
        expected_biz_code="ZHIBO_LIVE",
        expected_authorization_mode="DEVICE_LICENSE",
    )
except PdkClientError as exc:
    # 40321：管理员关闭；50350：部署未启用或 Handler 不可用
    show_maintenance_page(exc.message)
    raise
```

然后按顺序处理：

1. 拉取业务信息并确认 `effectiveStatus == AVAILABLE`；
2. 根据 `registrationMode` 显示或隐藏注册入口；
3. 从操作系统安全存储恢复完整会话快照；
4. 调用 `verify_session()` 验证恢复会话；
5. 失败则清空安全存储，显示登录页；
6. 登录成功后检查 `mustChangePassword`；
7. 加载账号/许可证状态后进入业务主界面。

界面功能也应以公开元数据中的 `supportedActions` 为准。例如当前 zhibo 聚合 Handler 返回 `AI_GENERATE`、`LIVE_CONTROL`、`LIVE_PUBLISH`、`ACCOUNT_SYNC` 和 `DETAIL_QUERY`；客户端不要展示运行实例未声明支持的动作。

`verify_session()` 适合在“恢复会话、应用回到前台、网络恢复、关键业务开始前”调用，不要机械地在每个 HTTP 请求前再调用一次，否则会把流量和延迟翻倍。最终授权仍由目标业务接口的服务端校验决定。

## 5. PDD（appId=1）完整流程

### 5.1 手机号短信注册

```python
client = PdkClient("https://api.example.com", 1, "13800138000",
                   require_https=True)

client.ensure_business_available(
    expected_biz_code="PDD",
    expected_authorization_mode="USER_SUBSCRIPTION",
)
client.send_sms("REGISTER")
registered = client.register(
    password="StrongPass123",
    sms_code=input("短信验证码: "),
    invitation_code="ABC123",  # 可选，只建立代理邀请关系
)
```

PDD 注册成功通常会直接返回登录态并自动开通试用。小号库存不足不会再回滚注册，而是返回 `resourceAllocated=false`；客户端应显示“账号和试用已开通，资源等待平台补充”，不能把它当成注册失败。

当前阿里云短信仅有配置和适配器外壳，尚未安装正式 SDK；生产短信能力在适配器完成前不能宣称已交付。固定验证码只允许 `local` Profile 使用，正式环境必须关闭。

### 5.2 PDD 登录与卡密核销

```python
client.login("StrongPass123")

# PDD 用户收到卡密后核销套餐；DEVICE_LICENSE 业务不要调用此方法。
client.activate_card(
    "PDK-1234-5678-9ABC",
    payment_channel="OFFLINE",
)
```

PDD 是用户级订阅和单设备绑定。新设备登录若账号仍绑定旧电脑，会返回 `40103`；必须在旧电脑解绑或由管理员后台解绑。

### 5.3 资源领取、解密和结果上报

```python
ROOT_SALT = load_from_secure_build_config()

lease, credential = client.acquire_token_decrypted(
    action_type="GOODS_COLLECT",
    goods_id="881920391204",
    root_salt=ROOT_SALT,
)

trace_id = lease["leaseTraceId"]
try:
    execute_business(credential)
except AccountBannedError as exc:
    client.report_result(trace_id, "FAIL_ACCOUNT_BANNED", error_message=str(exc))
except NetworkError as exc:
    client.report_result(trace_id, "FAIL_NETWORK", error_message=str(exc))
except Exception as exc:
    client.report_result(trace_id, "FAIL_BUSINESS", error_message=str(exc))
else:
    client.report_result(trace_id, "SUCCESS", duration_ms=1200)
```

`acquire-token` 请求必须带毫秒 `timestamp`；`PdkClient` 已自动添加。结果上报字段的真实名称是 `responseDurationMs`，SDK 也已封装。只有服务端判定成功时才按当前业务规则扣次。

业务资源的 AES-128-GCM + 时间窗 + 字节翻转密文，与第 10 节的 HTTP 信封是两套不同机制，不得混用。

## 6. DEVICE_LICENSE（appId=2/3）流程

### 6.1 账号与许可证来源

`ZHIBO_AI` 和 `ZHIBO_LIVE` 默认 `ADMIN_ONLY`：

1. 管理员或代理后台创建手机号账号和初始密码；
2. 后台选择套餐并给该手机号分配若干张卡密；
3. 一张卡密对应一个设备许可证；
4. 用户在客户端用手机号和密码登录；
5. 新设备收到 `40380` 后输入分配给自己的卡密，再调用同一个登录接口。

客户端不要显示短信注册或邀请码注册入口。调用注册接口会返回 `40322`。

### 6.2 首次设备绑定

```python
client = PdkClient("https://api.example.com", 3, "13454118763",
                   require_https=True)

try:
    login = client.login("InitialPass123")
except PdkClientError as exc:
    if exc.code != 40380:
        raise
    login = client.activate_device(
        "InitialPass123",
        card_key=input("请输入分配给本机的卡密: "),
    )
```

绑定规则：

- 本设备已有许可证：以后只需手机号、密码和稳定 deviceId；
- 新设备没有许可证：不带卡返回 `40380`；
- 卡密不属于当前手机号或业务：`40382`；
- 卡密已绑定其他设备：`40383`；
- 当前设备已绑定另一张卡：`40980`；
- 设备/卡密并发绑定冲突：`40981`，可短暂退避后重试一次；
- 首次激活时才开始计算 `expireAt`；解绑不会暂停有效期。

### 6.3 一手机号多卡多设备

统一方案支持同一手机号拥有多张卡：

- 10 张卡可分别绑定 10 台电脑，并形成 10 个独立许可证会话；
- 第 11 台电脑没有可用卡时，不能登录业务；
- 第 11 台不带卡返回 `40380`；使用已占用卡返回 `40383`；
- 同一手机号在其他设备上的许可证和直播不会被本机普通注销影响；
- 每张卡独立到期、独立解绑、独立续费和独立审计。

### 6.4 登录成功不等于业务可用

已到期的设备许可证仍可能允许登录，以便用户查看状态、续费历史、注销或解绑；付费业务接口会返回 `40381`。因此登录后读取：

```python
state = client.verify_session()
if not state["operationAllowedHint"]:
    show_restricted_page(state)
```

客户端可查询：

```python
current = client.device_license_current()
all_licenses = client.device_license_list()
renewals = client.device_license_renewal_history()
```

当前设备许可证按到期时间计费，服务端把次数设置为 `2147483647` 兼容旧校验。客户端应显示“按时长 / 不限次”，不要把该整数直接展示给用户。

若登录响应 `mustChangePassword=true`，必须阻止进入业务主界面：

```python
client.change_password("InitialPass123", "NewStrongPass456")
client.login("NewStrongPass456")
```

改密和短信重置密码都会使该手机号全部旧会话失效。

### 6.5 续费与解绑

续费由管理后台对原许可证办理，卡密不变，并产生新的续费/销售记录。客户端只刷新许可证状态，不创建销售记录。

```python
client.device_license_unbind()
```

解绑后当前 Token 失效，本地 SDK 自动清理 Token。用户可在新电脑用手机号、密码和原卡密重新绑定；原到期时间继续计算。

### 6.6 ZHIBO_AI 业务动作

ZHIBO_AI 没有推流票据接口。许可证有效后，可根据 `supportedActions` 使用通用资源调度，例如：

```python
lease, credential = client.acquire_token_decrypted(
    action_type="AI_GENERATE",
    goods_id="业务对象ID",
    root_salt=load_from_secure_build_config(),
)
try:
    run_ai_task(credential)
except Exception as exc:
    client.report_result(lease["leaseTraceId"], "FAIL_BUSINESS",
                         error_message=str(exc))
else:
    client.report_result(lease["leaseTraceId"], "SUCCESS")
```

资源租约与设备许可证是两层校验：有有效许可证不代表一定有可分配资源；资源不足仍可能返回 `50301/50302`。

## 7. ZHIBO_LIVE 视频推流

### 7.1 开始推流前

必须依次确认：

1. `appId=3 / bizCode=ZHIBO_LIVE`；
2. 会话有效；
3. 当前许可证 `status=ACTIVE`；
4. `expireAt > serverTime`；
5. 没有需要先停止的活动会话；
6. 为本次连接申请新的短效票据。

```python
client.ensure_business_available(
    expected_biz_code="ZHIBO_LIVE",
    expected_authorization_mode="DEVICE_LICENSE",
)
state = client.verify_session()
if not state["operationAllowedHint"]:
    raise RuntimeError("当前许可证不可推流")

ticket = client.live_publish_ticket(title="客户端直播")
publish_url = ticket["publishUrl"]  # 只在内存中短暂使用
session_no = ticket["streamSessionNo"]
```

### 7.2 把 URL 当作不透明的一次性秘密

`publishUrl` 已包含 MediaMTX 路径和短效鉴权票据：

- 不拆解、不修改；
- 不写日志、数据库、剪贴板或崩溃上报；
- 不展示完整 URL；
- 每次开播生成新的 `clientRequestId`；
- 断线或启动失败后丢弃旧 URL，不能让 FFmpeg 无限重放。

```python
import subprocess

process = subprocess.Popen([
    "ffmpeg", "-re", "-i", input_file,
    "-c:v", "libx264", "-f", "flv", publish_url,
])

# 正确日志：只记录 session_no，绝不打印完整参数数组。
logger.info("开始推流 session=%s publishUrl=[REDACTED]", session_no)
```

MediaMTX 会调用后端内部 HTTP Auth。没有通过客户端登录和票据接口获得合法 URL 的 FFmpeg 命令行推流会被拒绝。客户端绝对不能调用 `/api/v1/internal/mediamtx/**`。

### 7.3 查询与停止

```python
streams = client.live_streams_current()
client.live_stream_stop(session_no)
```

`40970` 表示 `clientRequestId` 重复；生成新 ID。`40971` 表示已有待推流或在线会话；先查询并停止旧会话，再申请新票据。

长时间直播可以每 30～60 秒刷新一次当前许可证，用于 UI 倒计时和本地主动停流。这是直播状态刷新，不是绕过服务端的授权心跳；MediaMTX 和服务端仍是最终裁判。

## 8. 稳定设备 ID 与会话保存

### 8.1 设备 ID

`PdkClient` 的顺序是：

1. `PDK_DEVICE_ID` 环境变量；
2. appId 隔离的本地缓存文件；
3. 主机信息哈希生成并落盘。

设备 ID 不应在每次启动时变化。重装系统、清理设备文件或修改构建 appId 都可能产生新设备，应按换机流程处理。

### 8.2 会话安全保存

```python
snapshot = client.export_session()
secure_store(snapshot)  # Windows DPAPI / macOS Keychain / Linux Secret Service

restored = PdkClient("https://api.example.com", 3,
                     device_id=snapshot["device_id"])
restored.restore_session(secure_load())
try:
    restored.verify_session()
except PdkClientError:
    restored.clear_session()
    secure_delete()
```

禁止把会话快照明文写入 JSON、日志或注册表。快照还可能包含 HTTP 信封的 AES 会话密钥：这是为了兼容服务端 30 分钟跨请求加密响应缓存；持久化 Token 时必须把整个快照一起安全保存。

## 9. 合法性检查与客户端状态

服务端在受保护请求上执行：

- appId 业务解析；
- Sa-Token 登录校验；
- 手机号、设备 ID 与会话一致性；
- DEVICE_LICENSE 的许可证归属、设备绑定、状态和到期检查；
- USER_SUBSCRIPTION 的用户归属、冻结状态和单设备绑定；
- 具体资源、次数和直播条件由对应业务 Service 再检查。

客户端的 `operationAllowedHint` 只用于界面提前提示，不能缓存成长期授权结论。建议状态：

```text
SIGNED_OUT
  -> AUTHENTICATING
  -> LICENSE_REQUIRED (40380)
  -> AUTHENTICATED_RESTRICTED (已到期/暂停)
  -> READY
  -> BUSINESS_RUNNING / STREAMING
  -> KICKED_OR_INVALID
```

收到 `40100/40102/40103/40106` 时 SDK 会清理内存 Token；客户端还要停止业务/媒体进程并删除安全存储中的旧会话。

## 10. 两层加密不要混淆

### 10.1 HTTPS 与 HTTP 请求信封

生产环境首先必须使用 HTTPS。可选信封是在 TLS 之上的额外 body 保护：

- 请求：RSA-OAEP(SHA-256/MGF1) 包装一次性 AES-256 密钥，AES-GCM 加密 JSON；
- 响应：服务端复用该 AES 密钥加密；
- `ts + rnd` 提供 5 分钟防重放；
- `off`：不使用信封；
- `optional`：明文和信封都接受；
- `force`：普通 JSON 返回 `42900`。

`PdkClient` 在 `auto_enable_crypto=True` 时收到 `42900` 会拉取公钥、开启信封并重试一次；`42901/42904` 会刷新密钥后重试一次。

生产环境必须预置 `public_key_pin`。仅从同一个 HTTP 响应读取公钥和指纹不能防止首次中间人替换，指纹应通过安装包配置、运维配置或其他可信渠道下发。

### 10.2 PDD 业务资源密文

`encryptedPayload` 使用另一套 AES-128-GCM + 10 分钟时间窗 + 报文字节翻转方案，只保护短效业务资源。`acquire_token_decrypted()` 已封装解密。

当前设计要求客户端持有 `root_salt`，安全性弱于服务端独占密钥；正式发布应通过安全构建配置注入，禁止使用仓库默认盐，并建议后续迁移为非对称或服务端会话密钥方案。

## 11. HTTP 调试记录

每次由 SDK 发出的业务请求都会产生脱敏记录，包含“请求什么、期待什么、实际返回什么”：

```python
import json

def show_http(record):
    print(json.dumps(record, ensure_ascii=False, indent=2))

client.on_http = show_http
```

示例：

```text
[请求] POST /api/v1/client/auth/login
[期待] code=200 并返回动态 tokenName/tokenValue；新设备可能先返回 40380
[实际] HTTP=200 code=40380 message=当前电脑尚未绑定许可证...
```

SDK 会遮蔽手机号、设备 ID、密码、短信码、卡密、Token、`encryptedPayload` 和 `publishUrl`。业务代码自己的日志、FFmpeg 日志和崩溃上报也必须使用同样的脱敏策略。

## 13. 关键错误码

| code | 含义 | 客户端动作 |
|---:|---|---|
| 0 | 网络失败 | 检查服务地址、网络和 TLS；只对幂等操作谨慎重试 |
| 40050 | appId 缺失或头/体不一致 | 检查构建配置 |
| 40100 | 登录态无效 | 停止业务、清会话、回登录页 |
| 40103 | 设备不一致或被踢 | 停止媒体/任务，重新登录或解绑 |
| 40105 | 密码错误 | 留在登录页，不自动重复提交 |
| 40106 | Token/许可证属于其他业务 | 清会话并检查固化 appId |
| 40301/40302 | PDD 套餐到期/配额耗尽 | 停止资源操作并引导核销或续费 |
| 40321 | 数据库业务关闭 | 进入维护页 |
| 40322 | 不开放自助注册 | 隐藏注册入口 |
| 40370～40373 | 直播越权、冻结、设备无效或旧套餐异常 | 停止推流并按 message 进入登录/受限页 |
| 40374 | 次数不足 | 停止业务并联系管理员 |
| 40380 | 新设备没有许可证 | 展开卡密框，用同一登录接口重试 |
| 40381 | 许可证到期 | 受限页；允许查询、注销、解绑 |
| 40382 | 卡密无效/不属于手机号 | 联系管理员核对 |
| 40383 | 卡密已绑定其他设备 | 先解绑原设备 |
| 40384 | 许可证暂停/作废 | 停止业务并联系管理员 |
| 40385 | 当前设备没有许可证 | 回到许可证绑定页 |
| 40970 | 推流请求 ID 重复 | 生成新 UUID |
| 40971 | 已有推流会话 | 查询并停止旧会话 |
| 40980/40981 | 设备已占用/并发绑定冲突 | 解绑或退避重试一次 |
| 42900～42904 | 信封模式、密钥、时间、防重放或解密错误 | 按 `PdkClientError.action` 处理 |
| 50350 | 部署未启用业务/Handler 不可用 | 维护页并联系运维 |
| 50370/50371 | MediaMTX 未启用/控制失败 | 禁止开播或查询状态后处理 |

不要对登录、卡密绑定、票据申请、结果上报做无条件自动重试；这些接口涉及会话、占用或幂等键。

## 14. 接入验收清单

- [ ] 客户端构建中固化正确 appId/bizCode，启动先校验业务元数据。
- [ ] 只用 `code == 200` 判断成功。
- [ ] 动态使用登录响应的 `tokenName`，不解析 Token。
- [ ] deviceId 跨重启稳定，并按 appId 隔离保存。
- [ ] PDD 根据 `registrationMode` 展示短信注册；管理员开户业务隐藏注册。
- [ ] 新设备收到 `40380` 后再展开卡密框，并用同一登录接口绑定。
- [ ] 支持一个手机号多张卡、多设备独立许可证，不做用户级单设备误判。
- [ ] 已到期许可证进入受限页，不把“登录成功”当作“业务可用”。
- [ ] 恢复会话后调用 `verify_session()`，失败清除系统安全存储。
- [ ] `publishUrl` 不进入日志、UI、剪贴板、数据库和崩溃上报。
- [ ] 每次推流使用新 `clientRequestId` 和新票据，断线不复用旧 URL。
- [ ] HTTP 日志能显示请求/期待/响应，并已脱敏。
- [ ] 生产使用 HTTPS、校验证书并预置公钥指纹。
- [ ] local 固定短信验证码未进入生产配置。
- [ ] PDD 的 `root_salt` 未使用仓库默认值，也未输出到日志。

## 15. 当前边界

1. `ZHIBO_AI`、`ZHIBO_LIVE` 种子默认关闭，联调前必须启用数据库业务并加入部署白名单。
2. 阿里云短信适配器仍是外壳，生产自助注册需先完成真实 SDK 接入。
3. `pdk_client.py` 不负责 Windows DPAPI/Keychain 等安全存储，也不负责启动/监控 FFmpeg；它提供安全边界明确的 API 和会话快照。
4. 软件升级系统目前是规格文档，尚未合并进本客户端接入链路。
5. 服务端是授权最终裁判；客户端本地检查只用于用户体验和主动停止业务。
