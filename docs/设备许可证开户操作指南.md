# 后台开户与设备许可证管理操作指南

> 适用范围：管理后台「设备许可证（DEVICE_LICENSE）」类业务的新客户开户与卡密分配。
> 本文以「给张老板开户 `ZHIBO_AI` 和 `ZHIBO_LIVE` 两个业务、手机号 `13454118763`、每个业务 10 台机器」为例完整说明。

---

## 0. 核心概念（先读，避免操作误解）

| 概念 | 说明 |
|---|---|
| **设备许可证模型** | 一张卡密对应一台电脑（设备）。卡密无限次使用，按**到期时间**计费。 |
| **激活才开始计时** | 到期时间不是分配时确定的，而是客户**第一次用这张卡密登录并绑定电脑**的那一刻才开始计算。刚分配完显示「未激活 · 暂不计时」是正常的。 |
| **「绑定业务」不是独立按钮** | 设备许可证模型下，用户按业务隔离（唯一约束为 `(bizId, phone)`）。给同一客户开多个业务 = 用**同一个手机号在多个业务下各建一个用户账号**。 |
| **套餐字段在设备许可证下的真实含义** | 只有「时长」真正生效；「独占帐号数 / 单次帐号数」在设备许可证下**不读取、不限制**（但建套餐时仍需填写以满足校验）。 |

---

## 1. 标准开户流程（4 步）

### 第 1 步：业务管理 —— 启用业务

- 进入 **业务管理**。
- `ZHIBO_AI`、`ZHIBO_LIVE` 在种子数据中默认状态为 **DISABLED**，需分别打开**启用**开关。
- 启用校验依赖：部署白名单 `PDD,ZHIBO`（已展开覆盖两码）+ 业务 Handler 已注册 + Handler 健康。三者均满足，可正常启用。
- ✅ 两个业务都必须先启用，否则后续建套餐会提示业务不可用。

### 第 2 步：套餐版本 —— 创建套餐

进入 **套餐版本** 页，为每个业务各创建套餐。字段填写说明：

| 字段 | 后端字段 | 设备许可证下是否生效 | 填写建议（10 台机器场景） |
|---|---|---|---|
| **时长** | `durationHours` | ✅ **生效**，决定每张卡到期 | **必填**。如 `720`=30 天、`8760`=365 天 |
| **独占帐号数** | `accountCount` | ❌ 不读取（分配数量由分配时的 `count` 决定） | 可填 `10` 与机器数保持一致，但不强制 |
| **单次帐号数** | `callsPerAccount` | ❌ 忽略（设备许可证次数恒为无限） | 随意填（如 `1`），不限制使用 |
| 标价 / 折扣率 / 名称 | — | 计费展示用 | 按实际填写 |

> ⚠️ 注意：建套餐接口要求业务**先可用**（即第 1 步已启用），所以顺序一定是「先启用再建套餐」。
> 当前建套餐时 `accountCount` / `callsPerAccount` 仍被**强制必填**（校验 `@NotNull`），但它们对设备许可证无效——这是已知的设计瑕疵，建档时照常填值即可，不影响功能。

### 第 3 步：用户管理 —— 添加用户（即绑定业务）

- 进入 **用户管理** → **添加用户**。
- **关键**：给张老板同时开两个业务，需**添加两次用户**：
  1. 手机号 `13454118763`，业务选 `ZHIBO_AI` → 保存（生成 User A）；
  2. 手机号 `13454118763`，业务选 `ZHIBO_LIVE` → 保存（生成 User B）。
- 系统按 `(业务, 手机号)` 唯一约束，两个业务各有一条独立用户记录，互不影响。
- 创建用户时选择的业务 = 该用户的绑定关系，没有单独的「绑业务」动作。

### 第 4 步：设备许可证 —— 分配卡密

进入 **设备许可证** 页：

1. 顶部「选择许可证业务」下拉选 `ZHIBO_AI`。
2. 「选择手机号」下拉选 `13454118763`（即张老板的该业务用户），或直接在输入框粘贴手机号后点「按手机号查找」。
3. 点 **分配卡密 / 席位** 按钮 → 弹窗：
   - **套餐**：选第 2 步创建的 `ZHIBO_AI` 套餐；
   - **许可证数量**：填 `10`（= 10 台机器，对应 10 张卡密，`count` 上限 500）；
   - **销售备注**：选填。
4. 点 **生成并分配** → 弹出「新生成的卡密」窗口。
   - ⚠️ 列表只显示**脱敏卡密**，此处弹窗显示**完整卡密**。
   - 关闭窗口前务必**复制并安全保存**，通过安全渠道发送给客户（建议同时用「导出卡密」留服务器存根）。

对 `ZHIBO_LIVE` 重复上述 1–4 步（选业务为 `ZHIBO_LIVE`、对应的套餐、数量 `10`）。

> 客户拿到卡密后，在客户端用卡密登录，首次成功登录即绑定一台电脑并开始计时。一张卡密绑定一台设备；如需换机器，可在后台对该许可证做「解绑」。

## 2. 日常运维操作（同一页面）

| 操作 | 按钮 | 说明 |
|---|---|---|
| 查询许可证 | 查询许可证 | 按业务 + 用户展示该客户所有卡密与状态 |
| 续费 | 续费 / 批量续费 | **原卡密不变**，仅延长到期时间（时长从续费套餐的 `durationHours` 累加）。对尚未激活的许可证续费，时长会从续费时刻起算 |
| 解绑 | 解绑 | 解绑后有效期继续流逝，正在推流会被停止 |
| 暂停 / 恢复 | 状态按钮 | 临时停用 / 恢复许可证 |
| 作废 | 作废 | 吊销该卡密，客户无法再使用 |
| 导出卡密 | 导出卡密 | 生成 `手机号_业务名_当前时间.csv`（仅手机号和卡密两列，UTF-8 BOM，Excel 可打开），并留存服务器存根 |
| 删除该客户此业务 | 删除该客户此业务 | 物理删除该客户在此业务下的全部授权数据（设备许可证、对应卡密、绑定设备），数据不可恢复，删除后该客户无法登录/使用本业务 |

## 3. 常见疑问与坑位

- **为什么设备许可证页下拉只有一个业务？**
  该页只显示授权模型为 `DEVICE_LICENSE` 的业务；用户级套餐（`USER_SUBSCRIPTION`）业务请去「卡密与授权 → 激活码池」管理。若你期望看到的业务不在 `DEVICE_LICENSE` 列表内，说明它不是设备许可证模型。

- **为什么建套餐要填「单次帐号数」却不起作用？**
  设备许可证按到期时间计费、次数无限，`accountCount` / `callsPerAccount` 对它无效。强制必填是建套餐接口的通用校验（同一接口也服务用户级套餐），属设计瑕疵，不影响功能。

- **同一客户开多个业务，用同一个手机号创建多个用户，没问题吗？**
  没问题。系统按 `(业务, 手机号)` 区分，不同业务下是独立用户行，各持各的许可证。

- **刚分配完显示「未激活 · 暂不计时」？**
  正常。到期从客户首次登录激活那刻起算，未激活不计时。
