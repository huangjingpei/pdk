# PDK 客户端接入指南（Python SDK）

> 配套文件：`client/python/pdk_client.py`（单文件、零业务依赖，可直接拷入项目）。
> 底层协议细节见 `docs/protocol-encryption-design.md`；本指南只讲「怎么用 SDK 把客户端接进来」。

---

## 1. 环境与依赖

```bash
pip install requests cryptography
```

`pdk_client.py` 仅依赖 `requests` 与 `cryptography`，无其他业务依赖，可直接复制进任意 Python 项目。

---

## 2. 最小接入（30 秒跑通）

```python
from pdk_client import PdkClient

# 1) 构造客户端（deviceId 自动持久化到机器级目录，重装/重启不丢）
c = PdkClient("http://localhost:8080", app_id=2, phone="13454118763")

# 2) 新设备首次登录需带卡密（卡密即激活设备许可证）；已绑定设备可只传密码
res = c.login(password="YourPass123", card_key="PDK-XXXX-XXXX-XXXX")
print(res["tokenName"], res["tokenValue"])
print("许可证:", res.get("deviceLicense"))

# 3) 之后所有受保护接口自动带令牌与设备指纹回传头
print(c.profile())
```

登录成功后，`PdkClient` 自动保存：
- `token` / `token_name`：后续请求自动通过 `satoken` 头携带；
- `fingerprint_hash`：服务端下发的指纹哈希，自动通过 `X-PDK-FP` 头回传，供服务端做「无心跳的克隆/换机检测」；
- `device_name`：服务端回显的设备名。

---

## 3. 登录与许可证生命周期

| 场景 | 调用 | 说明 |
|---|---|---|
| 新设备激活 | `login(password, card_key="PDK-...")` | 卡密绑定到当前设备，生成许可证 |
| 已绑定设备登录 | `login(password)` | 省略 card_key，复用既有许可证 |
| 换设备 / 重装 | 先 `unbind_device()` 或 `device_license_unbind()`，再在新机 `login(card_key=...)` | DEVICE_LICENSE 业务：解绑后有效期继续计算 |
| 会话自查 | `verify_session()` | 读 profile，返回 `license_status` / `expire_at` / `expired`，业务前主动判断 |
| 注销 | `logout()` | 清除服务端会话 |
| 改密 | `change_password(old, new)` | 需旧密码 |
| 找回密码 | `send_sms()` → `reset_password(sms_code, new)` | 不需旧密码，成功后旧会话被踢 |

**关键约定**：`deviceId` 必须**稳定**。SDK 默认持久化到机器级目录（见第 5 节），请勿每次登录随机生成，否则会被服务端判定为「换机」并触发风控。

---

## 4. 传输加密（应用层信封）

后端 `encryptionMode` 由管理后台「系统设置 → 安全 → 协议加密模式」控制，三态：

| 模式 | 行为 | 客户端怎么做 |
|---|---|---|
| `off` | 信封一律当明文透传，加密客户端不可用 | `use_crypto=False`（默认） |
| `optional` | 信封解密 + 明文放行；仅当请求加密时才加密响应 | `use_crypto=False` 可灰度并存；`True` 则全加密 |
| `force` | 只接受加密信封，明文一律拒 `42900` | **必须** `use_crypto=True` |

### 4.1 开启加密

```python
c = PdkClient(base_url, app_id, phone, use_crypto=True)
# 之后所有带 body 的请求自动加密、响应自动解密，业务代码无感知
res = c.login(password="...", card_key="...")
print(c.profile())   # GET 响应由服务端用会话密钥加密、SDK 自动解密
```

### 4.2 模式自适应（推荐）

`auto_negotiate=True`（默认）时，SDK 在首次请求前自动拉取 `/config/public` 并按 mode 协商：
- `force` 且你没开 `use_crypto` → 立即抛 `PdkClientError(42900)`，提示开启加密；
- `off` 且你开了 `use_crypto` → 打印告警（服务端不会解密信封）。

也可显式握手提前暴露问题：

```python
c = PdkClient(base_url, app_id, phone, use_crypto=True)
cfg = c.connect()          # 拉公开配置 + 校验兼容性
print(cfg["encryptionMode"], cfg["kid"])
```

### 4.3 公钥指纹钉扎（防 MITM，默认开）

`/config/public` 每次下发 `publicKeyFingerprint`（公钥 DER 的 SHA-256 前 16 字节）。SDK 首次将指纹存入机器级目录并**钉扎**；之后每次拉取都比对，不一致即抛错拒绝连接（疑似中间人替换公钥）。

```python
c = PdkClient(base_url, app_id, phone, use_crypto=True, pin_fingerprint=True)  # 默认即 True
```

> 调试提示：开发环境若服务端未配置固定私钥（每次重启公钥变化），钉扎会误报。临时关闭：`pin_fingerprint=False`，或给服务端配置固定 `pdk.crypto.private-key-pem`（见设计文档）。

## 5. 设备 ID 与硬件指纹

### 5.1 deviceId 持久化

SDK 自动管理 `deviceId`，存储位置（所有语言 SDK 统一约定）：
- **Windows**：`%ProgramData%\PDK\{app_id}\device_id`（机器级、普通用户可读写、重装不丢）；
- **其他 / 不可写**：`~/.pdk_client/{app_id}/device_id`。

> 刻意**不用注册表 / 用户目录**：避免同机多用户下 deviceId 变 per-user 导致业务/账号身份错乱，也避免与机器级硬件指纹在克隆检测中误判。

如需自定义，构造时传 `device_id="..."` 即可，SDK 不再自动生成。

### 5.2 硬件指纹（克隆/换机检测）

`login()` 默认自动采集指纹（Windows 经 WMI 取主板/磁盘/CPUID），随登录上报。服务端对原始组件做 salted hash，**绝不落库明文**。也可手动传：

```python
c.login(password="...", card_key="...", fingerprint={
    "motherboardSerial": "...", "diskSerial": "...", "cpuid": "..."
})
```

## 6. 跨语言接入必读（避坑清单）

若你要把同样的后端接成 C++ / C# / Go / Electron 等客户端，**以下任一条不对齐都会失败**：

1. **RSA-OAEP 必须显式写死 `MGF1=SHA-256`**。Java 默认 `MGF1=SHA-1`，与全客户端不一致 → 恒 `42904`。Python SDK 已正确设置。
2. **响应信封的 `enc` 恒为空串**。解密用「本次请求使用的同一把 AES 会话密钥」，`enc` 直接忽略。
3. **错误响应也可能被加密**。只要请求是信封，`42901`/`42904` 等错误也会用会话密钥加密返回——读 `code` 前必须先解密。
4. **`deviceId` 必须稳定且每次请求都带 `X-PDK-Device-ID`**。服务端按 `appId+deviceId` 缓存会话密钥，deviceId 一变，无 body 的 GET 响应会**静默降级为明文**（客户端很难察觉）。
5. **只加密 HTTP body**，URL / query / header 全部明文。敏感参数（密码、卡密）必须放 body，不能放 query。
6. **AES-GCM tag 拼接**：Java/Python 都把 16 字节 tag 附在密文尾部，天然兼容；C++/OpenSSL 需手动 `EVP_CTRL_GCM_GET_TAG` 拼接、`SET_TAG` 拆分。
7. **防重放**：信封含 `ts`（毫秒时间戳，服务端 ±5 分钟窗口）与 `rnd`（16 位随机串，服务端一次性去重）。不要复用 `rnd`，不要偏离系统时间过远。

## 7. 错误码

| code | 含义 | 客户端处理 |
|---|---|---|
| `200` | 成功 | 返回 `data` |
| `40001` | 参数校验失败（如设备ID为空） | 检查请求体字段；若在 `off` 模式发了信封，会落到此码（预期外，应改 mode 或关加密） |
| `40100` | 登录状态无效或已过期 | 重新 `login()` |
| `42900` | 服务端强制加密，明文被拒 | 开启 `use_crypto=True` |
| `42901` | 密钥版本不匹配（kid 不存在） | 检查信封 `kid` 是否为服务端下发的 `kid` |
| `42902` | 时间戳超时（防重放窗口外） | 校准客户端系统时间 |
| `42903` | 随机串重放（rnd 重复） | 每次请求使用新随机 `rnd` |
| `42904` | 解密失败 / 信封格式错误 / 无会话密钥 / 公钥指纹不符 | 检查 MGF1=SHA-256、会话密钥、指纹钉扎 |
| 其他 | 业务错误（许可证过期、卡密无效等） | 按 `message` 提示用户 |

所有非 200 均抛 `PdkClientError(code, message, raw=...)`，可用 `try/except PdkClientError as e:` 捕获。

## 9. 接入自检清单

- [ ] `pip install requests cryptography` 完成
- [ ] `deviceId` 稳定持久化（不每次随机）
- [ ] 登录后令牌/指纹自动回传（SDK 已处理，勿手动覆盖 header）
- [ ] 若服务端为 `force`，构造 `PdkClient(..., use_crypto=True)`
- [ ] 加密客户端：确认 RSA-OAEP `MGF1=SHA-256`（跨语言必查）
- [ ] 解密响应时忽略 `enc` 字段、使用请求会话密钥
- [ ] 读错误响应的 `code` 前先判断是否为信封并解密
- [ ] 敏感参数只放 body，不放 URL/query
- [ ] 生产环境保留 `pin_fingerprint=True`，并给服务端配置固定私钥
- [ ] 业务前调用 `verify_session()` 自查许可证有效性
