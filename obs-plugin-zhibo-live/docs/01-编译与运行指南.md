# PDK 智播云控 OBS 插件 - 编译与运行指南

本文档介绍 **PDK 智播云控 OBS 插件 (`obs-plugin-zhibo-live`)** 的开发环境准备、Release / Debug 双模式编译、快速安装部署以及日常调试运行方法。

---

## 一、 开发环境与先决条件

### 1. 系统要求
* **操作系统**：Windows 10 / 11 64 位 (x64)
* **编译器**：Visual Studio 2022 (MSVC v143 64-bit)，需在 VS Installer 中勾选 **“使用 C++ 的桌面开发”**
* **构建工具**：CMake 3.20 或更高版本
* **Qt 框架**：Qt 6.5+ ~ Qt 6.9+ (x64 MSVC 构建版，如 `C:\Qt\6.9.2\msvc2022_64` 或 `C:\Qt\6.5.3\msvc2022_64`)
* **运行宿主**：OBS Studio 29.0 或更高版本（推荐 30.2+ 64位）

### 2. 自包含依赖库说明
为了彻底解决跨机器克隆工程时缺少依赖库的问题，本项目已将核心头文件和静态导入库全部收敛至工程根目录的 `deps/` 目录：
```text
obs-plugin-zhibo-live/
├── deps/
│   ├── obs-studio-headers/    # OBS C/C++ 核心与前端 API 头文件 (已修复 408 字节 ABI)
│   └── lib/
│       ├── obs.lib            # libobs 64位链接导入库
│       └── obs-frontend-api.lib # obs-frontend-api 导入库
```
**无需在本地全量编译 OBS Studio 庞大源码仓库，开箱即可构建。**

## 二、 双模式编译指南 (Release vs Debug)

本项目在底层严格约定了 **“编译版本决定运行环境”**，无需用户在界面手动配置任何复杂的服务端地址或 RTMP 地址：

| 编译模式 | 注入宏定义 | 默认运行环境 | 后端 API 地址 | 默认 RTMP 接入地址 | 适用场景 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Release** | `PDK_RELEASE_BUILD`, `NDEBUG` | `PRODUCTION` (生产环境) | `https://pdk.graddu.com` | `rtmp://43.248.187.207:1935` | 正式交付发布、线上部署 |
| **Debug** | `PDK_DEBUG_BUILD`, `_DEBUG` | `LOCAL_DEBUG` (本地联调) | `http://127.0.0.1:8080` | `rtmp://127.0.0.1:1935` | 本地开发调试、新功能测试 |

### 1. Release 模式编译（正式发布）
使用根目录提供的一键脚本或 CMake 命令行：
```cmd
# 方式 A：双击运行一键构建脚本
build.bat

# 方式 B：手动使用 CMake 命令行
cmake -B build -S . -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release --parallel
```
* **输出文件**：`build\Release\obs-zhibo-live.dll`
* **多语言文件**：`assets\locale\zh-CN.ini`

### 2. Debug 模式编译（本地调试）
```cmd
cmake -B build -S . -G "Visual Studio 17 2022" -A x64
cmake --build build --config Debug --parallel
```
* **输出文件**：`build\Debug\obs-zhibo-live.dll`

### 3. 特殊环境变量覆盖 (开发应急)
如果由于特殊网络环境需要临时将通信指向其他 IP，无需重新编译代码，直接在操作系统设置环境变量即可：
```cmd
set PDK_BASE_URL=http://192.168.1.100:8080
```
插件启动时若检测到 `PDK_BASE_URL`，会自动优先使用该地址。

## 三、 插件部署与安装

### 1. 一键自动安装 (推荐)
编译完成后，以管理员身份运行工程根目录下的：
```cmd
install.bat
```
脚本会自动检查 OBS 运行状态，并将 DLL 及语言包部署到默认路径：
* `C:\Program Files\obs-studio\obs-plugins\64bit\obs-zhibo-live.dll`
* `C:\Program Files\obs-studio\data\obs-plugins\obs-zhibo-live\locale\zh-CN.ini`

### 2. 手动拷贝部署规范
若 OBS 安装在其他盘符，手动拷贝遵循以下结构：
```text
<OBS安装目录>\
├── obs-plugins\
│   └── 64bit\
│       └── obs-zhibo-live.dll                   <-- 放这里
└── data\
    └── obs-plugins\
        └── obs-zhibo-live\
            └── locale\
                ├── zh-CN.ini                    <-- 放这里
                └── en-US.ini
```

## 四、 运行与功能验证

### 1. 启动与首次激活
1. 启动 OBS Studio 64位；
2. 插件随 OBS 启动自动加载：
   * **首次使用**：会自动弹出 **“智播云控 - 客户端设备激活”** 对话框，界面显示当前环境（绿色 `生产环境` 或黄色 `本地调试`）；
   * **输入凭据**：输入注册手机号、登录密码及分配的设备卡密（格式：`PDK-XXXX-XXXX-XXXX`）；
   * **点击激活**：成功后服务端建立 1:1 设备席位绑定，状态变更为 `已激活 (正常)`，同步显示到期时间与调用次数。
3. **二次启动**：后续打开 OBS 将执行后台静默认证，无需重复输入卡密。

### 2. 活动流自动探测与接入
1. 在智播推流客户端（如智播豆）点击 **“开始直播推流”**；
2. 插件后台线程以 5 秒周期探测到活动流，OBS 当前场景会自动出现名为 **“智播拉流源”** 的官方流媒体源，画面与声音实时接入；
3. 推流停止时，插件感知并在 5 秒内平稳清空媒体源，避免 OBS 后台反复重连。

### 3. 渠道去重变异双滤镜验证
插件在激活弹窗中默认勾选 **“启用渠道去重变异”**：
* 在 OBS 场景中右键点击 **“智播拉流源”** -> 选择 **“滤镜”**：
  * **上方【音频/视频滤镜】**：已自动挂载 `智播渠道去重-音频微调`（纯真人声保真微调）；
  * **下方【效果滤镜】**：已自动挂载 `智播渠道去重-画面微调`（GPU Shader 亚像素微裁与微色温）。
* 也可以在任意通用来源上手动点击 `+` 号添加：
  * `OBS Channel Variant - Video`
  * `OBS Channel Variant - Audio`

## 五、 日志查看与故障排查

### 1. 日志文件路径
* **OBS 运行日志目录**：
  `%APPDATA%\obs-studio\logs`
  （按时间命名，如 `2026-09-08 03-30-00.txt`，搜索 `[ZhiboLive]` 可查看所有插件日志）
* **插件本地持久化配置**：
  `%APPDATA%\obs-studio\plugin_config\obs-zhibo-live\config.json`

### 2. 常见问题排查速查表

| 现象 | 可能原因 | 解决办法 |
| :--- | :--- | :--- |
| **OBS 顶部“工具”菜单没有插件入口** | 插件 DLL 未能加载，可能缺少 VC++ 运行库或安装路径错误 | 查看最新 OBS 日志，检索 `obs-zhibo-live` 是否报错；安装 Visual C++ 2015-2022 x64 Redistributable |
| **弹窗提示“该卡密已绑定其他设备”** | 该卡密已在原设备激活，PDK 实施 1:1 设备绑定 | 在管理后台（或通过接口）解绑原设备，或更换新卡密激活 |
| **推流后 OBS 没有自动拉流** | 1. 登录已失效或卡密过期<br>2. 手机号/设备与推流端不一致 | 检查激活弹窗状态是否为 `ACTIVE`；确认推流端与拉流端登录的是同一个账号体系 |
| **滤镜列表中找不到去重滤镜** | 旧版 DLL 结构体尺寸超标被 OBS 拦截 | 确认已部署最新编译的 Release DLL，结构体大小已严格锁定 408 字节 |
